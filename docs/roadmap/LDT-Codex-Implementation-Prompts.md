# LDT Supplement: Codex Implementation Prompts

**Purpose:** Ready-to-use prompts for implementing the expanded PRD in Codex.

---

## Prompt 1: Release Metadata Source of Truth

Implement a typed release metadata source of truth for LDT.

Tasks:

1. Add a `ReleaseMetadata` TypeScript schema.
2. Add a server-side provider `getReleaseMetadata(countryCode)`.
3. Replace hard-coded country counts, local-unit counts, data years, and release labels on public pages with provider values.
4. Ensure exports include release ID, data year, methodology version, and published timestamp.
5. Add tests to ensure home page/country page metadata comes from the provider.

Constraints:

- Do not change existing analytics behavior.
- Preserve existing Supabase/local fallback pattern but make it explicit.
- Add clear empty/loading/error states.

## Prompt 2a: AI Brief Cache and Run Store

Implement the v1.5 AI Brief Cache and Run Store for every LLM-backed AI brief step.

Tasks:

1. Define stable AI stage names for the current brief routes.
2. Create or expand an `ai_runs` table with cache key, source fingerprint, input hash, prompt version, model settings, retrieval IDs, output payloads, citations, caveats, status, token usage, cost, and timestamps.
3. Add utilities for deterministic cache-key generation and source-fingerprint invalidation.
4. Add a shared read-through cache wrapper that checks for a successful cached run before calling the LLM.
5. Convert each LLM-backed AI brief route to use the wrapper.
6. Return provenance to the frontend: generated now, loaded from cache, stale, or failed.
7. Add an explicit regenerate path that bypasses cache and creates a new run record.
8. Include AI run IDs, cache status, prompt version, model, source fingerprints, retrieval IDs, and caveats in Markdown exports.
9. Add tests for cache hits, cache misses, failed runs, prompt-version invalidation, and source-fingerprint invalidation.

Constraints:

- Do not overwrite prior AI outputs.
- Failed, stale, or superseded runs must not be returned as cache hits.
- Public users should not be able to trigger uncontrolled regeneration.
- The same locality and unchanged evidence state should reload the same saved output by default.

## Prompt 4: Investment Opportunity Finder MVP

Implement the Investment Opportunity Finder MVP.

Requirements:

1. Define opportunity families and deterministic trigger rules.
2. Generate opportunities only when evidence triggers exist.
3. Link every opportunity to evidence records: indicators, score drivers, plan passages, geospatial/hazard flags.
4. Display caveats and evidence gaps.
5. Add review controls: draft, analyst reviewed, counterpart discussed, rejected, escalated.
6. Do not use AI to invent opportunities; AI may only summarize rationale from linked evidence.
